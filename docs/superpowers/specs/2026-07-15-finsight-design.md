# FinSight — платформа фінансової аналітики витрат

**Дата:** 2026-07-15
**Статус:** дизайн затверджено користувачем (Yana), очікує ревʼю специфікації
**Тип проєкту:** пет-проєкт / навчання

## 1. Мета

Веб-платформа, де користувач підключає свій Monobank (або вмикає демо-дані),
бачить красиву аналітику своїх витрат, може купити преміум через WayForPay
(тестовий режим) і спілкуватися з AI-агентом про свої витрати.

## 2. Ключові рішення (затверджені)

| Питання | Рішення |
|---|---|
| Призначення | Пет-проєкт для навчання; платежі — тестовий режим WayForPay |
| Синхронізація Monobank | Тільки кнопка «Оновити» (без webhook), працює локально |
| Джерело даних на час розробки | Демо-генератор транзакцій; справжній Monobank підключається токеном пізніше |
| AI-агент | Планується в архітектурі, будується останнім етапом (потрібен ключ Anthropic) |
| Преміум-фіча | Розширена аналітика: вся історія, порівняння місяців, експорт у Excel |
| Вхід | Email + пароль через Supabase Auth |
| Тема | Світла |
| Навігація | Бічний анімований сайдбар (згортається до іконок), компоненти з 21st.dev через Magic MCP |
| Дашборд | Картки-підсумки зверху, під ними графіки |
| Архітектура | Next.js (App Router) — фронтенд і серверні API-роути в одному проєкті |

## 3. Архітектура

```
Браузер користувача
   │
   ▼
Next.js-додаток (сторінки + серверні API-роути)
   │                    │
   ▼                    ▼
Supabase              Зовнішні сервіси:
(Postgres +           • Monobank Personal API
 Auth)                • WayForPay (тестовий режим)
                      • Claude API (етап 4)
```

**Принцип безпеки:** усі секрети (токен Monobank, секретний ключ WayForPay,
ключ Anthropic, service-ключ Supabase) живуть лише на сервері — в `.env.local`
(не комітиться в git) та в серверних API-роутах. У браузер вони не потрапляють.

**Стек:** Next.js + TypeScript + Tailwind CSS, компоненти з 21st.dev (Magic MCP),
графіки — Recharts (або аналог, узгоджений з компонентами 21st.dev),
Supabase JS SDK.

## 4. Сторінки

1. **/login, /register** — вхід і реєстрація (email + пароль, Supabase Auth)
2. **/dashboard** (головна після входу):
   - 4 картки-підсумки: витрати цього місяця, середнє за день, найбільша покупка, баланс картки
   - Графік витрат по днях (лінія або стовпчики)
   - Кільцева діаграма по категоріях
3. **/transactions** — повний список транзакцій: пошук, фільтр по категоріях,
   кнопка «Оновити з Monobank»
4. **/assistant** — чат з AI-агентом (етап 4; до того — вкладка з заглушкою «Скоро»)
5. **/settings**:
   - Перемикач джерела даних: «Демо-дані» / «Мій Monobank»
   - Поле для токена Monobank + список підключених карток
   - Блок «Преміум»: статус, кнопка «Купити Преміум»

Неавторизованого користувача з внутрішніх сторінок перекидає на /login.

## 5. База даних (Supabase Postgres)

| Таблиця | Зміст |
|---|---|
| `profiles` | id (= auth user id), email, is_premium, premium_until, data_source ('demo' / 'monobank') |
| `monobank_tokens` | user_id, зашифрований токен (шифрування на сервері, ключ у `.env.local`) |
| `accounts` | user_id, monobank account id (або 'demo'), назва картки, валюта, баланс |
| `transactions` | user_id, account_id, час, опис, сума (копійки, відʼємна = витрата), MCC-код, категорія, залишок після операції, is_demo |
| `payments` | user_id, order id, сума, статус WayForPay, дата |

**Row Level Security увімкнено на всіх таблицях:** користувач читає і пише лише
рядки зі своїм user_id. Серверні роути з service-ключем — єдиний виняток
(запис транзакцій, активація преміуму).

**Категорії:** MCC-код (стандартний код типу торгівця від банку) мапиться в
~10–12 українських категорій з іконками: Продукти, Кафе і ресторани, Транспорт,
Здоровʼя, Розваги, Комуналка і звʼязок, Шопінг, Подорожі, Перекази, Інше.
Мапа MCC → категорія — окремий модуль, спільний для демо- і реальних даних.

## 6. Дані: демо-режим і Monobank

### Демо-режим (типовий для розробки)
- Генератор створює ~4–6 місяців реалістичних транзакцій (Сільпо, АТБ, Glovo,
  Uklon, кафе, аптеки, підписки) з правдоподібними сумами, датами і MCC-кодами
- Вмикається перемикачем у налаштуваннях; нова реєстрація за замовчуванням
  отримує демо-дані, щоб дашборд ніколи не був порожнім
- Демо-транзакції позначені `is_demo = true`; перемикання на Monobank ховає їх

### Monobank (реальні дані)
1. Користувач отримує токен на api.monobank.ua і вставляє в «Налаштуваннях»
2. Сервер перевіряє токен запитом `client-info`, зберігає картки в `accounts`,
   токен — зашифрованим у `monobank_tokens`
3. Кнопка «Оновити» → серверний роут → Monobank `statement` → нові транзакції
   в базу (дедуплікація за monobank id транзакції)

**Обмеження Monobank (враховано в дизайні):** 1 запит на 60 секунд на токен,
максимум 31 день історії за запит. Тому:
- перший імпорт: останні 31 день одразу
- повна історія (преміум): фонове завантаження місяць за місяцем з паузою 60 с
  та індикатором прогресу; переривання не ламає дані — наступний запуск
  продовжує з останнього завантаженого місяця

**Помилки:** невалідний токен → зрозуміле повідомлення в налаштуваннях;
перевищення ліміту запитів → «Зачекайте хвилинку і спробуйте ще раз»;
Monobank недоступний → показуємо збережені дані з припискою про час
останнього оновлення.

## 7. Преміум і WayForPay

**Модель:** одна покупка = преміум на 30 днів (100 грн у тестовому режимі,
реальні гроші не списуються).

**Безкоштовно:** аналітика за останні 30 днів.
**Преміум:** уся історія транзакцій, порівняння місяців (цей vs минулий),
експорт транзакцій у Excel (.xlsx).

**Потік оплати (без редіректу, віджет на нашому сайті):**
1. Кнопка «Купити Преміум» → серверний роут готує параметри платежу і підпис
   (HMAC-підпис секретним ключем мерчанта — тільки на сервері)
2. Фронтенд відкриває офіційний спливаючий віджет WayForPay поверх сторінки
3. Після оплати віджет повертає результат у браузер
4. Браузер повідомляє наш сервер → сервер **сам перевіряє статус платежу
   через API WayForPay** (браузеру не довіряємо) → ставить `is_premium = true`,
   `premium_until = now + 30 днів`, пише рядок у `payments`
5. Інтерфейс одразу показує «Преміум ⭐» і відкриває преміум-функції

Дані мерчанта (merchantAccount, secretKey) Yana передає не в чат, а кладемо
в `.env.local`. Використовуємо тестовий режим WayForPay.

## 8. AI-агент (етап 4)

- Вкладка-чат: питання про власні витрати вільною мовою, відповіді українською
- Потік: питання → серверний роут → Claude API (tool use): модель має
  інструменти для агрегованих запитів **лише до транзакцій поточного
  користувача** (суми за період, топ категорій, найбільші/нетипові покупки)
- Ключ Anthropic — у `.env.local`; вартість — центи за запит, Yana створює
  ключ на цьому етапі за покроковою інструкцією
- Історію чату в базі не зберігаємо (поза обсягом першої версії)

## 9. Етапи реалізації

Кожен етап — окремий план реалізації (writing-plans) і працююча платформа в кінці:

1. **Каркас:** Next.js-проєкт, Supabase (проєкт + таблиці + RLS), реєстрація/вхід,
   сайдбар з 21st.dev, порожні сторінки, захист роутів
2. **Дані й дашборд:** демо-генератор, мапа категорій, підключення Monobank,
   кнопка «Оновити», картки-підсумки, графіки, сторінка транзакцій
3. **Преміум:** WayForPay-віджет, серверна перевірка платежу, активація преміуму,
   обмеження «30 днів безкоштовно», повна історія, порівняння місяців, експорт у Excel
4. **AI-агент:** чат-інтерфейс, серверний роут з Claude API і tool use

## 10. Тестування і перевірка якості

- Розробка і перевірка кожного етапу — на демо-даних (реальний токен банку
  не потрібен до самого кінця)
- Юніт-тести для чистої логіки: мапа MCC → категорія, агрегації для карток
  і графіків, генератор демо-даних, перевірка підпису WayForPay
- Ручна перевірка потоків у браузері після кожного етапу: реєстрація → вхід →
  дашборд з даними → оплата тестовою карткою → преміум активовано
- RLS перевіряємо окремо: другий тестовий користувач не бачить чужих даних
